### 👤 이지현

#### Admin Payment

- 관리자 결제내역에 결제 상품의 실제 이용 상태 추가
- 이용권과 스터디룸 예약 상태를 관리자 결제 화면에서 공통 상태로 표시하도록 Mapping 구성
  - `READY` : 사용 전
  - `USING` : 이용 중
  - `COMPLETED` : 이용 완료
  - `PENDING` : 결제 진행 중
  - `CANCELED` : 취소 완료
- Payment History 응답에 `usageStatus`, `reservationStatus` 추가
- 관리자 결제 목록 및 상세 화면에 상품 이용 상태 표시
- 이미 이용 중이거나 이용 완료된 상품의 결제 취소 제한
- 스터디룸은 `CONFIRMED` 상태인 이용 전 예약만 결제 취소 가능하도록 Frontend 검증
- 결제 취소가 불가능한 경우 사유를 확인할 수 있도록 UI 보완

#### Payment / Receipt

- 결제 완료 화면에 `영수증 받기` Button 추가

- `GET /api/commands/{commandId}`를 이용하여 RTOS 처리 결과 확인
- RTOS Command가 `COMPLETED`가 될 때까지 Polling 처리
- 출력 완료 시 `✓ 영수증 출력 완료` 상태 표시
- 출력 실패 및 응답 지연 Error Handling 추가
- 중복 영수증 출력 방지
- 영수증 출력 중에는 자동 로그아웃 Countdown 일시 정지
- 출력 시작 시 자동 로그아웃 Countdown을 다시 10초로 설정
- 영수증 Button 및 출력 상태 UI 추가
- 2026.08.18 Work Log 작성 및 반영

#### Device Health Check

- RTOS `/api/devices/health` 요청을 `DeviceService`와 연결
- Health Check의 Network·Door·Card Reader·Printer 값을 `DeviceStatus`로 변환
- 장치별 Health Check 수신 시 `lastConnectedAt` 갱신
- 현재 시연 환경을 장치 타입별 활성 장치 1대 기준으로 처리
- Network 상태를 `NORMAL / OFFLINE / ERROR`로 변환
- Door 상태를 `NORMAL / OFFLINE / ERROR`로 변환
- Card Reader 상태를 `NORMAL / OFFLINE / ERROR`로 변환
- Printer 상태를 `NORMAL / OFFLINE / ERROR`로 변환
- Health Check 상태가 실제 변경된 경우에만 `DeviceLog` 저장
- `HEALTH_STATUS_CHANGE` Event Log 추가

#### Device Offline Detection

- `DeviceHealthScheduler` 추가
- 5초 간격으로 활성 장치의 마지막 Health Check 수신 시간 확인
- 마지막 통신 후 20초가 초과된 장치를 `OFFLINE`으로 변경하도록 구현
- OFFLINE 전환 시 `HEALTH_TIMEOUT` Device Log 저장
- 이미 OFFLINE인 장치는 동일 Log를 반복 생성하지 않도록 처리
- Health Check를 한 번도 수신하지 않은 장치는 OFFLINE 판정에서 제외
- OFFLINE 자동 감지 기능은 후속 테스트 필요

## 💬 주요 논의 및 결정

### RTOS Health Check 역할 분담

- 장원진이 RTOS Card Reader 연동을 진행 중이므로 Health Check Backend 연동은 이지현이 이어서 작업하기로 결정
- RTOS가 `/api/devices/health`로 상태를 전달하면 Backend에서 Device 상태와 `lastConnectedAt`을 갱신하도록 역할 분담

### 장치 구성 기준

- 프로젝트 시연 환경에서는 장치 타입별 기기가 1대씩 존재하는 것으로 가정
- `NETWORK`, `DOOR`, `CARD_READER`, `PRINTER` 타입별 활성 장치 1대를 기준으로 Health Check 상태를 반영하기로 결정
- RTOS 및 Backend Health Check 구현도 해당 기준으로 진행

### 영수증 출력 방식

- 초기에는 카드 결제 완료 후 영수증을 자동 출력하는 방식 검토
- 스터디카페에서는 주문번호표가 필요하지 않으며 사용자가 영수증을 원하지 않을 수도 있다는 점 논의
- 결제 완료 화면에서 사용자가 직접 `영수증 받기`를 선택할 수 있도록 별도 Button을 제공하는 방식으로 결정
- 영수증 출력 중 자동 로그아웃으로 화면이 종료되지 않도록 Countdown을 일시 정지하도록 처리

### 스터디룸 결제 대기 예약

- 사용자가 스터디룸 예약 시간을 선택하면 해당 시간대를 다른 사용자가 동시에 선택하지 못하도록 `PENDING_PAYMENT` 상태로 임시 점유
- 기존 결제 대기 유지시간 30분은 지나치게 길다고 판단
- 미결제 예약 자동 취소 시간을 5분으로 단축하기로 결정
- 5분 동안 결제가 이루어지지 않으면 예약을 `CANCELED` 처리하여 시간대를 다시 선택 가능하게 함
- 사용자가 결제 과정에서 X Button을 눌러 직접 취소하는 경우에는 5분을 기다리지 않고 즉시 임시 예약을 취소하기로 결정
- 직접 취소 후 해당 예약 시간대를 다른 사용자가 다시 선택할 수 있도록 처리

### 관리자 결제 취소 기준

- 결제 완료 여부만으로 결제 취소 가능 여부를 판단하기에는 정보가 부족함
- 실제 상품이 아직 사용 전인지 확인할 수 있어야 함
- 이용권은 `TicketUsageStatus`, 스터디룸은 `ReservationStatus`를 결제 History와 함께 조회하기로 결정
- 관리자 결제관리 화면에 상품 이용 상태를 표시하고 이용 전 상품에 대해서만 결제 취소 기능을 제공하도록 개선
