## 💬 주요 논의 및 결정

### RTOS Command 상태 전이 및 중복 처리

- 전일 RTOS Command를 Memory에서 DB 저장 구조로 변경한 뒤 실제 상태 전이를 검증하기로 함
- Command 처리 Flow를 `PENDING → PROCESSING → COMPLETED / FAILED` 기준으로 확인
- RTOS가 이미 처리한 Command에 Finish 요청이 다시 들어오는 경우 상태가 재변경되지 않아야 함
- `PROCESSING` 상태인 작업만 완료·실패 처리하도록 Entity 단계에서 상태 검증을 추가
- 중복 완료 및 중복 실패 요청은 예외 처리하여 Command 처리 이력의 일관성을 유지하기로 결정

### 로그아웃 중복 방지 복구

- 로그아웃 중복 호출 방지를 위한 Flag가 API 실패 상황에서도 정상적으로 초기화되어야 함
- 로그아웃 요청을 의도적으로 실패시킨 뒤 다시 정상 로그아웃할 수 있는지 테스트
- API 성공 여부와 관계없이 후속 로그아웃이 차단되지 않도록 복구 Flow 점검

### 회원 전용 Route 보호

- 로그아웃 후에도 회원 전용 화면에 직접 접근할 수 있는 QA 실패 사례 확인
- Frontend Route 수준에서도 Token 및 인증 상태를 검증할 필요가 있다고 판단
- `/loginhome`, `/mypage`를 `UserPrivateRoute`로 감싸 비인증 접근을 차단하도록 개선

### 외출 자동 퇴실 정책
