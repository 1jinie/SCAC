## 💬 주요 논의 및 결정

### 시연 환경 및 사용자 Flow

- 키오스크는 공용 장치이므로 사용자 작업 완료 후 이전 사용자의 인증·선택·결제 상태가 남지 않도록 초기화 범위를 명확하게 관리
- 결제 완료 후 사용자가 추가 작업을 이어갈 경우에는 로그인 상태를 유지할 필요가 있으므로 전체 초기화와 결제 관련 초기화를 분리
- 키오스크 전체 사용자 Flow에서 Browser 기본 Alert보다 공통 Modal UI를 사용하는 방향으로 개선
- 현재 사용 중인 스터디룸도 미래 시간대를 예약할 수 있으므로 현재 Room 상태만으로 선택 자체를 제한하지 않도록 수정

### RTOS 연동

- RTOS 측 기능만으로는 실제 프로젝트 연동을 완료할 수 없으므로 Spring Backend에 Command 처리 구조 추가 필요
- 우선 DeviceCommand 관련 Entity·Repository·DTO 골격을 생성하고 실제 API 및 Command 처리 기능은 후속 구현

### 시연 QA

- 참여기업 시연을 통해 실제 사용자 관점에서 키오스크 및 관리자 기능을 확인
- 시연 과정에서 발견된 오류와 실무 개선 의견을 이후 QA 및 기능 개선 우선순위에 반영하기로 함
