- Device 테이블은 장치의 현재 정보를 관리하고, DeviceLog는 상태 변경 이력을 저장하도록 역할을 분리
- DeviceLog가 Device의 `device_id`를 FK로 참조하도록 변경
- 장치 삭제 시 연결된 로그도 삭제되도록 `ON DELETE CASCADE`를 적용

## 🗄️ DB 변경 사항

### 1. Device 테이블 추가

- 장치의 현재 정보와 상태를 저장하는 `device` 테이블 추가
- 주요 컬럼
  - `device_id` : 장치 PK
  - `device_name` : 장치 이름
  - `device_type` : 장치 유형
  - `status` : 현재 장치 상태
  - `location` : 설치 위치
  - `ip_address` : 장치 IP 주소
  - `last_connected_at` : 마지막 연결 시간
  - `created_at` : 장치 등록 일시
  - `serial_number` : 장치 고유 시리얼 번호
- 장치 유형·상태·설치 위치 조회를 위한 인덱스 추가
- `serial_number`에 UNIQUE 제약조건 적용

### 2. DeviceLog 테이블 수정

- 기존 장치명 저장 방식에서 `device_id` FK 참조 방식으로 변경
- `device.device_id`와 DeviceLog 연결
- 장치 삭제 시 관련 로그도 함께 삭제하도록 `ON DELETE CASCADE` 적용
- 장치별 상태 및 생성 일시 조회를 위한 복합 인덱스 추가
- 전체 로그 생성 일시 조회를 위한 인덱스 추가

### 3. TicketUsage 상태 변경

- 기존 `ACTIVE` 상태 제거
- 이용권 사용 상태를 `USING`으로 통합
- TicketUsage 관련 Backend 로직에 변경된 상태값 반영
