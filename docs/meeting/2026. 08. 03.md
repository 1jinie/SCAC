## 💬 주요 논의 사항

### 관리자 로그인 방식

- 관리자 Frontend에서 전화번호와 별도의 관리자 ID 중 어떤 값을 사용할지 논의
- 일반 사용자와 관리자는 서로 다른 인증 흐름을 사용하므로 관리자 전용 ID를 사용하는 방향 검토
- Backend와 DB에 관리자 `loginId` 및 비밀번호 구조가 반영되어 있음을 확인
- 관리자 계정은 DB에 등록된 정보만 로그인을 허용하는 구조임을 확인
- Backend의 관리자 인증 구조를 기준으로 관리자 Frontend를 수정하기로 논의

### Device Door 기능

- Device 도메인에 구현되지 않은 Door 관련 파일을 삭제할지 유지할지 논의
- 실제 출입문 및 기타 기기 제어는 RTOS가 담당할 예정임을 확인
- 실제 장치 연동은 추후 담당 선생님과 함께 진행하기로 논의
- 현재 단계에서는 Door 관련 구조를 삭제하지 않고 구현을 보류하기로 함

### 통합 테스트 및 QA

- 인증부터 퇴실까지의 전체 흐름을 우선 검증하기로 함
- 결제 오류를 우선 수정하고 결제 승인 후 이용권 발급 여부를 확인하기로 함
- 관리자 기능은 기본 의존성과 골격을 먼저 구성한 뒤 기능 단위로 테스트하기로 함

## 🎯 결정 사항

- 관리자 로그인은 전화번호가 아닌 `loginId`와 비밀번호를 사용
- 관리자 `loginId`는 영문 소문자로 입력받도록 구성
- 관리자 계정은 DB에 사전 등록된 계정만 로그인을 허용
- 관리자 Frontend는 Backend 관리자 인증 구조를 기준으로 수정
- Device의 Door 관련 파일은 삭제하지 않고 구현 보류 상태로 유지
- 실제 Door·프린터 등 장치 연동은 RTOS 연동 단계에서 담당 선생님과 진행
- 핵심 사용자 흐름 통합 테스트와 결제 오류 수정을 우선 진행
