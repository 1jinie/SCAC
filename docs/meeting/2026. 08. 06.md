### 👤 장원진
### 좌석 / 예약 / 입실·퇴실 · Git 관리

#### Meeting Room Reservation

- 관리자 스터디룸 상세 화면에서 현재 이용 중인 예약 정보 조회
- 현재 이용 사용자의 전화번호 표시
- 예약 시작 및 종료 예정 시간 표시
- 관리자 좌석·예약 화면의 상태 표기를 `예약됨` 대신 `사용중`으로 통일
- 스터디룸 상태 변경 Entity 메서드 추가

#### Reservation Scheduler

- 스터디룸 예약 상태 자동 변경 스케줄러 구현
- 1분 간격으로 현재 예약 시간 확인
- 예약 시작 시간이 된 `CONFIRMED` 예약을 `IN_USE`로 변경
- 예약 시작 시 스터디룸 상태를 `USR`로 변경
- 예약 종료 시간이 된 `IN_USE` 예약을 `COMPLETED`로 변경
- 종료 후 해당 방에 다른 이용 중 예약이 없으면 스터디룸 상태를 `AVB`로 변경
- 예약 시작·종료 시간 및 상태 기반 Repository 조회 메서드 추가

#### TicketUsage / Check-in

- 사용 가능한 이용권을 구매일 기준 오래된 순서로 조회하도록 보완
- 입실 준비 시 가장 오래된 사용 가능 이용권을 우선 조회
- 현재 사용 중인 이용권이 만료되면 다음 READY 이용권 조회
- 다음 이용권이 존재하면 자동 활성화
- Check-in의 `usageId`를 다음 이용권으로 변경
- 다음 사용 가능한 이용권이 없으면 자동 퇴실
- 시간권과 기간권 시작 로직 분리
- 시간권 종료 후 다음 이용권으로 연속 이용 가능하도록 구현
- 기간권 종료 후 다음 이용권 전환 흐름 추가
- 자동 퇴실 시 좌석 해제 및 SystemLog 기록

## 💬 주요 논의 및 결정

### 여러 이용권 보유 시 사용 순서

- 사용자가 여러 개의 이용권을 구매할 수 있도록 허용
- 이용권 구매 시 이미 사용 가능한 이용권을 보유하고 있다면 추가 구매 여부를 안내
- 사용자가 직접 사용할 이용권을 선택하는 기능은 제공하지 않음
- 시스템이 정해진 우선순위에 따라 이용권을 자동 적용하기로 결정

#### 시간권 + 시간권

- 먼저 구매한 이용권부터 사용하는 선입선출 방식 적용
- 현재 이용권 종료 후 다음 시간권으로 자동 전환

#### 시간권 + 기간권

- 사용자가 현재 입실 중이라면 현재 사용 중인 시간권을 우선 적용
- 현재 입실 상태가 아니라면 기간권을 우선 적용

#### 기간권 + 추가 이용권

- 현재 사용 가능한 기간권을 우선 적용
- 기간권 종료 이후 다음 이용권을 적용

### 이용권 추가 구매

- 이미 사용 가능한 이용권이 있어도 추가 구매 자체는 허용
- 결제 전 기존 이용권 보유 사실을 사용자에게 안내
- 사용자가 계속 구매를 선택하면 결제 진행
- 이용권 사용 순서는 시스템에서 자동 결정

## ⚠️ 확인 필요 사항

- 현재 구현된 READY 이용권 자동 전환은 구매일 기준 오래된 이용권을 조회하는 구조
- 시간권과 기간권이 혼합된 경우의 우선순위가 회의에서 결정한 규칙과 완전히 일치하는지 추가 검증 필요
