## 🎯 결정 사항

- `TicketUsage`와 입실(Check-in) 도메인을 분리하여 관리
  - `TicketUsage` : 사용자가 보유한 이용권의 사용 상태 및 이용 정보 관리
  - `Check-in` : 좌석 입실·외출·재입실·퇴실 상태 및 기록 관리

- 입실 및 외출 기록 관리를 위한 `Check_InOut` 테이블 구조 확정

- 퇴실 처리 및 기록 유지를 고려하여 `seat_id`를 Nullable로 설정

- 반복적인 외출·재입실 흐름을 관리하기 위해 `away_end_at` 컬럼 추가

- `penalty_end_date`는 해당 날짜까지 이용 제한이 적용되는 것으로 결정
  - 예: `2026-08-10` → 8월 10일까지 이용 불가, 8월 11일부터 이용 가능

- 사용자 취소와 관리자 취소를 구분하지 않고 `결제 취소` 상태로 통합

- 결제 취소 상태 명칭은 `CANCELED`로 통일

## 🗄 DB 변경 사항

### Check_InOut 테이블 추가 및 구조 보완

입실·외출·재입실·퇴실 기록 관리를 위해 별도의 Check_InOut 테이블을 구성함.

| 컬럼명 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| checkin_id | BIGINT AUTO_INCREMENT | X | 체크인 고유 ID, PK |
| user_id | BIGINT | X | 사용자 ID, FK |
| seat_id | BIGINT | O | 좌석 ID, FK |
| usage_id | BIGINT | X | TicketUsage ID, FK |
| checkin_at | TIMESTAMP | X | 입실 및 재입실 시각 |
| checkout_at | TIMESTAMP | O | 퇴실 시각 |
| away_start_at | TIMESTAMP | O | 외출 시작 시각 |
| away_end_at | TIMESTAMP | O | 외출 종료 및 재입실 시각 |
| checkin_status | VARCHAR(50) | X | USING, AWAY, CHECKOUT |
| created_at | TIMESTAMP | X | 당일 최초 입실 시각 |

### 구조 보완 사항

- 퇴실 처리 흐름을 고려하여 `seat_id` Nullable 적용
- 반복적인 외출 및 재입실 기록을 위해 `away_end_at` 컬럼 추가
- DB 반영 및 구조 수정 : 김수영

### 결제 내역 조회용 View 추가

- 관리자 결제 내역 조회를 위한 DB View 생성
